## 一、统一编制和独立编制

**统一编址**
逻辑上 IO 地址和内存地址是一致的。

**独立编址**
单独画出一个区域给 IO。

## 二、程序查询方式

- 特点：对低频率的设备效果好；对高频率的设备，设备会一直独占 CPU，效果不好。
- 程序查询阶段没有 DMA 和中断处理，遇到慢速设备时 CPU 只能等。

## 三、程序中断方式原理过程

### 完整的中断处理流程（三阶段）

**第一阶段：中断隐指令（硬件自动完成）**
当程序 A 执行到某一条指令结束时，CU 检测到了中断请求。CPU 马上暂停程序 A，中断隐指令开始工作，它只干三件事，简记为「关、保、引」：

1.关中断：CPU 把 PSW 中的允许中断标志位（IF）清零。为什么要关？因为接下来要保存重要数据，不能被别的事情打扰。
2.保存断点：把当前 PC 的值（也就是程序 A 下一条该执行的指令地址）和 PSW 的值，自动压入系统堆栈（由 SP 指针控制）保存起来。这就好比在作业本上夹了个书签，记下看到哪一页了。
3.引出中断服务程序：硬件根据中断源的类型，去「中断向量表」里找到对应的中断向量，把这个地址直接送入 PC。

**第二阶段：执行中断服务程序（软件完成，即程序 B）**
因为 PC 被修改成了程序 B 的入口地址，下一个 CPU 周期，CPU 自然就转去执行程序 B。程序 B（中断服务程序）通常包含以下步骤：

1.保护现场：用汇编指令（如 PUSH）把 CPU 里其他寄存器的值（比如通用寄存器 R0、R1，里面存了程序 A 计算到一半的数据）也推入堆栈保存起来。
2.设备服务（真正的程序 B）：执行中断的核心任务。例如把键盘输入的字符读入内存，或者处理网络数据包。
3.恢复现场：事情办完了，用汇编指令（如 POP）把刚才保存在堆栈里的通用寄存器的值原封不动地弹回来。

**第三阶段：返回程序 A（软硬结合）**
中断服务程序的最后一条指令必定是一条特殊的中断返回指令（如 IRET）。当 CPU 执行到 IRET 时，硬件会自动把系统堆栈里压着的旧 PC 和旧 PSW 弹回对应的寄存器中。

开中断：恢复了旧的 PSW，自然也就重新允许中断了。

因为 PC 又变回了程序 A 被中断时的下一条指令地址，CPU 继续若无其事地往下执行程序 A。

### 多重中断与屏蔽字

- 单重中断：当系统处理一个中断请求，就不再理会别的中断。
- 多重中断：允许高优先级的中断嵌套进来。
- 屏蔽字：有选择地选中那些重要的中断，不重要的中断就被屏蔽了。原理是给当前的中断一个保护，如果不想让某些中断打断它，就把对应中断的屏蔽触发器设为 1。
- 中断优先级包括响应优先级和处理优先级。响应优先级由硬件决定，不可改变；处理优先级通过中断屏蔽字确定，是软件实现的。

### 一个完整的场景示例

CPU 现在正在运行一个长时间占据 CPU 的程序，这时候鼠标和键盘也在不停地输入数据。当这个程序的一条指令结束，就在中断周期看是否有中断请求。这时候鼠标和键盘可能都有一个请求，它们各自 USB 那里的中断控制器就收到了请求，然后通过优先级判断，把键盘请求给到 CPU。CPU 根据这个请求的序号，经过映射或者运算得到了这个设备的驱动地址，然后运行这个驱动程序，打出字母。

同时，当按下某一个键的时候，这个键的数据就写入了数据寄存器里，然后 CPU 运行这个键盘的驱动程序来读取这个数据，然后显示出来。

## 四、DMA 方式

**DMA 控制器的组成**
1.数据寄存器
2.数据源地址
3.数据目的地址
4.计数器

**工作流程**
比如从磁盘向内存传递五个数据。先把源地址、目的地址和计数器都写好，然后每一个数据先通过数据寄存器，再到目的地址，这样工作。第五步是向 CPU 发送一个中断信号来告诉它结束了。

**关键特性**
- DMA 控制器是用来处理块设备的（以块为单位）。
- 对于正常的访问运行过程，CPU 就不能和主存通信了，因为总线被别的程序使用。而对于 DMA 来说，它有一条专用的 DMA 总线来访问主存，所以可以在传递数据的过程中还进行程序的运行。
- 虽然 DMA 和 CPU 都有一条总线和主存连接，但主存不能同时支持两个设备的读写，于是出现一些方式来提高效率。

**时序要点**
- DMA 和中断请求同时发生时，优先响应 DMA 请求。
- DMA 传输请求在每一个机器周期结束就会发出；而 DMA 结束请求是在一个指令结束的时候发出。
- 周期挪用的情况下，DMA 收到一点数据，就会在一个机器周期结束时发送数据。
- CPU 和 IO 接口中，主存的地址是不需要交换的。

## 五、三种方式的选择

- 程序查询阶段没有 DMA 和中断处理，遇到慢速设备时 CPU 只能等。
- 有中断处理和 DMA 的情况：高速大吞吐量的设备给 DMA，慢速设备给 CPU 自己处理。

## 三种IO方式的优缺点

### 一、 三种 I/O 方式对比
以下是去掉表格中 `*` 斜体标记，改为序号/纯文本后的 Markdown 表格：

| **I/O 方式** | **核心工作原理** | **主要优点** | **主要缺点** | **适用场景** |
| --- | --- | --- | --- | --- |
| **1. 程序查询方式（Polling I/O）** | CPU 轮询检查设备状态寄存器的“准备好”标志位，直到数据准备就绪才进行传输。 | 1. 硬件电路简单，无需额外的中断控制器。<br>2. 逻辑直观，易于实现。 | 1. **CPU 效率极低**（处于“忙等”状态，浪费大量的 CPU 周期）。<br>2. 无法并发处理其他任务。 | 1. 结构极简的嵌入式系统/单片机。<br>2. 设备极少且对实时性要求极高、数据传输极快的专有场景。 |
| **2. 中断驱动方式（Interrupt I/O）** | CPU 发出 I/O 指令后继续执行其他程序；设备准备好数据后向 CPU 发起中断请求，CPU 暂停当前程序并转去执行中断服务程序完成数据传送。 | 1. **解脱 CPU 的忙等**，CPU 与 I/O 设备实现部分并行。<br>2. 响应及时，能够处理突发事件。 | 1. 每次传输**以字节/字为单位**，数据量大时频繁中断 CPU。<br>2. 中断上下文切换（保护/恢复现场）带来不小的开销。 | 1. 中低速字符设备（如键盘、鼠标、串口通信）。<br>2. 需实时响应突发事件的设备。 |
| **3. DMA 方式（Direct Memory Access）** | 由专门的 DMA 控制器（DMAC）接管总线，直接在主存与 I/O 设备之间进行**块级别**的数据传输，仅在整块数据传输结束时中断 CPU。 | 1. **CPU 干预极少**（仅在初始化和结束时干预）。<br>2. 传输速率高，数据直接进出内存，无需 CPU 搬运。 | 1. 硬件结构复杂，成本较高。<br>2. 存在总线争用问题（周期挪用/窃取）。 | 1. 高速、大批量数据传输设备（如硬盘/SSD 读写、网卡数据包收发、显卡帧缓冲区刷新）。 |

### 二、 场景选择决策指南

1. **按“设备传输速率与数据量”选择**：  
    - **小数据量、极低速** $\to$ **中断驱动方式**（如：敲击键盘按键，触发一次中断传一个字节）。
    - **大数据量、高速** $\to$ **DMA 方式**（如：从 NVMe 硬盘读取 4KB 的数据块，或者通过万兆网卡接收数据帧）。
    - **无需多任务的简单硬件监控** $\to$ **程序查询方式**（如：简单单片机定时查询传感器状态）。
2. **按“CPU 干预频率”递减**：
$$\text{程序查询方式（全程干预/忙等）} > \text{中断驱动方式（每个字节干预一次）} > \text{DMA 方式（每个数据块干预一次）}$$
