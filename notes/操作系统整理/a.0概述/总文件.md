## 一、操作系统的发展与分类

计算机操作系统的发展，大致分为以下几个阶段，每个阶段都是在前一阶段的痛点上改进：

**1. 手工操作阶段**
- 缺点：用户独占全机，人机速度矛盾导致资源利用率极低。

**2. 单道批处理系统**
- 优点：缓解了一点程度的人机速度矛盾，资源利用率提升了一些。
- 缺点：内存中只有一道程序运行，CPU 大量时间在空闲，利用率还是不高。

**3. 多道批处理系统**
- 优点：支持了并发执行，利用率大幅提升。
- 缺点：用户响应时间长，没有人机交互的功能，无法中途更改和调试。

**4. 分时操作系统**
- 优点：解决了人机交互的问题，允许多个用户使用同一台计算机。
- 缺点：过于公平，不能优先处理紧急任务。
- 特点：主要用于交互式作业，对响应时间有要求。

**5. 实时操作系统**
- 优点：能处理紧急任务，实现了可靠性和及时性。

**关于并发性的补充**
上面这些早期的操作系统都不需要并行性，直到多道程序处理系统出现之后，才支持并发性。

## 三、操作系统的运行机制

### 中断与异常

- 不同程序的并发实现，也需要中断。
- 发生中断的时候，会进行状态的切换，进入内核态。
- 但访问某些非特权操作的时候，不一定会发生状态切换。
- 参考机组的中断向量，中断发生时会进入内核态。

### 系统调用的过程

1. 执行一个程序，当需要用到一些特权操作时，就会进入内核态。
2. 进入系统调用的入口程序。
3. 通过传入的参数，它来执行对应的内核程序。
4. 执行完毕之后，返回用户态。

## 四、操作系统的体系结构

五种结构对比（原始笔记此处标题为「大内核 vs 微内核」，具体展开在图中）：

| 结构 | 优点 | 缺点 |
|---|---|---|
| 分层结构 | 容易调试和测试 | 不能跨层调用，利用率低 |
| 模块化 | 逻辑清晰，方便开发，效率高 | 模块相互依赖，难调试和验证 |
| 宏内核（大内核） | 效率高，都在一个内核里 | 牵一发动全身，某个出错，整个系统崩溃 |
| 微内核 | 容易维护，内核可靠性高 | 效率低，频繁切换用户态、核心态 |

## 五、操作系统的引导流程

整体流程如下：

```
[硬件通电]
   │
   ▼
1. BIOS（硬件自检 + 读取磁盘第0磁道的 MBR）
   │
   ▼
2. MBR（执行主引导代码 → 扫描分区表 → 寻找「活动分区」）
   │
   ▼
3. PBR（跳转到活动分区的首扇区 → 读取并执行分区引导记录）
   │
   ▼
4. 启动管理器（PBR 引导根目录下的 Boot Manager，如 Windows 的 bootmgr 或 Linux 的 GRUB）
   │
   ▼
[加载系统内核 → 开机完成]
```

分步说明：

1. 首先通电后执行 BIOS 的引导程序，它先进行硬件自检，没问题之后，就将主引导程序 MBR 读入内存。
2. MBR 被读入内存然后执行，它会扫描磁盘引导程序，然后扫描分区表。
3. 扫描分区表，就是去找操作系统所在的分区，读入引导记录 PBR。
4. 然后在根目录找到完整的系统初始化程序（启动管理器）并执行，完成开机等动作。
