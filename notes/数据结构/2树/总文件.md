## 并查集（Disjoint-Set Union, DSU）核心笔记
### 1. 服务对象与核心使命
* **它管什么？**
* 专管“圈子/连通性”问题（只问“你俩是不是一伙的/能不能连通”，绝不问“谁是谁的亲爹”）。
* 适用于大量**原本地位平等的无向点**（如社交好友圈、局域网连通、图的最小生成树判环、网格岛屿连通）。
* **核心心法**：
* 树的上下级只是程序员为了**高效标记**而人为发明的“工具结构”。
* 根节点的唯一物理意义就是这个圈子的“圈主/法定代表人”。
* 判断两点是否在同一个集合，只看 $\text{Find}(x) == \text{Find}(y)$。
---
### 2. 底层存储与初始状态
* **双亲数组 `parent[]**`：
* `parent[i]` 存的是 $i$ 的直接父节点；如果 `parent[i] == i`（或存负数），说明它头上没人，自己就是根节点。
* **初始状态（开局全是 1）**：
* 没有任何预先长好的树，所有人最初都是孤立的单节点，高度 `rank = 1`。
* 后续所有的树枝，**100% 是由代码在处理加边事件时亲手连上去的**。
---
### 3. 两大核心操作与双重优化
#### 核心一：查找（Find）与【路径压缩】（事后救火）
* **基本动作**：顺着 `parent` 指针一路向上找根节点。
* **路径压缩（神级优化）**：
* 查找回溯时，**顺手把沿途路过的所有直系节点，直接改挂在最终根节点的正下方**。
* **关键避坑点**：
* 路径压缩是“单兵作战”，只能拍扁当前查的那条线；子树里其他没被查到的小弟，依然可能埋在深处。
#### 核心二：合并（Union）与【按秩合并】（事前防范）
* **基本动作**：先通过 `Find(x)` 和 `Find(y)` 找到各自的终极根节点 $rx$ 和 $ry$。**永远是大老板和大老板谈合并，绝不拿底层小弟去挂接。**
* **按秩合并（矮挂高）**：
* **为什么不能随便挂？** 如果小树当爹、大树当儿子，大树底下一大群没被查过的小弟**会被集体垫高一层**，极易被恶意数据拉成极深的长单链表导致爆栈。
* **矮树并入高树（`rank` 小的认 `rank` 大的当爹）**：整棵合并后的树总深度不增加，从源头杜绝深链条。
* **高度（`rank`）何时才会变？**
* 矮挂高时：高度不变，`rank` 不动。
* **只有两棵树一模一样高（`rank[rx] == rank[ry]`）合并时**：总高度才必然增加 1，此时新根节点的 `rank` 执行唯一的自增操作：`rank[rx] += 1`。
---
### 4. 运行结果与复杂度本质
* **单次操作时间复杂度**：
* 仅用路径压缩，均摊时间就已经极快；
* **路径压缩 + 按秩合并**同时使用，单次操作均摊复杂度为极其夸张的 **$O(\alpha(n))$**（反阿克曼函数）。
* 实际运行中对于人类已知的任何 $n$（哪怕是 100 亿），$\alpha(n) \le 4$。**在工程与算法中，直接视为纯常数 $O(1)$。**
* **对“充分压缩”的纠偏**：
* 哪怕没有预先做到让每一个小弟都被查过，在双优化的护航下，最坏单次查询也绝不会超过几十步，并在首次查询的那一瞬间直接就地压平。
---
### 5. 极简可背诵模板（Python / C++ 思路）
```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [1] * n  # 初始每个人的高度都是 1
    def find(self, x):
        # 路径压缩：回溯时直接挂到根节点脸上
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]
    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False  # 本就在同一圈子（在图论里意味着连这条边会成环）
        # 矮树并入高树，防树变深
        if self.rank[rx] < self.rank[ry]:
            self.parent[rx] = ry
        elif self.rank[rx] > self.rank[ry]:
            self.parent[ry] = rx
        else:
            self.parent[ry] = rx
            self.rank[rx] += 1  # 唯有等高合并，树高才会 +1
        return True
```

## 大根堆 堆排序
### 1.大根堆组成
1.首先一个完全无序的数组，放入二叉树或者是大根堆这种树形结构中，
2.不断自下向上进行堆化，注意：堆化顺序是自下向上的，可是堆化实现的结果是不断下沉
3.一直重复，得到了一个二叉树，根节点就是该数组最大值
### 2.堆化
1.以当前输入节点为根节点，不断比较左右子树和根节点，让最大值当根，然后替换
2.如果发生了替换就继续向下遍历让子树作为输入节点重复步骤，直到到底，或者没有发生替换
### 3.堆排序
1.以大根堆为基础，将得到的最大值取出，
2.让叶子节点放入根节点的位置，然后对根节点进行一次堆化，得到的新的根节点
就是目前数组的最大值
3.重复步骤，直到二叉树就一个元素，即实现了排序
### 要点：
1.大根堆组成的时候进行了多次堆化
2.进行堆排序的时候每一次一个最大值就是一个堆排序

## 大根堆与堆排序 (Heap & Heap Sort) ai
### 1. 大根堆的构建 (Build Heap)
1. **物理存储**：无需额外树形指针，连续数组通过数学下标（父 $i$，左孩子 $2i$，右孩子 $2i+1$）直接映射为完全二叉树。
2. **建堆起点**：所有叶子节点天然满足堆性质，故从**最后一个非叶子节点（$\lfloor n/2 \rfloor$）**开始，倒序遍历至根节点（下标 1）。
3. **宏观与微观**：
   * **宏观推进**：自底向上（遍历父节点下标递减：$n/2 \to 1$）。
   * **微观动作**：对每个节点执行**向下堆化（下沉 / Sift Down）**，使得每一棵局部子树逐步合格，最终整棵树满足“父大子小”。
4. **复杂度**：自底向上建堆的时间复杂度是极其优异的 **$O(n)$**（利用底层节点多但下沉路径短的几何级数错位相减得出）。
---
### 2. 向下堆化 (Sift Down / 下沉逻辑)
以当前节点为“擂主”，在当前堆的有效范围内向下比拼：
1. 找出当前节点的**左孩子、右孩子与自身之中的最大值**。
2. 若最大值不是当前节点：
   * 将最大值孩子与当前节点**互换**（当前节点下沉一层）；
   * **关键递归/循环**：下沉后可能破坏下方子树的堆性质，必须以换下去的位置为新起点，**继续向下比较下沉**，直到它比左右孩子都大，或已经沉到底部（成为叶子）。
3. 时间复杂度：单次下沉最多走树的高度，即 **$O(\log n)$**。
---
### 3. 堆排序全过程 (Heap Sort)
本质是用 $O(\log n)$ 的下沉代价替代了暴力选择排序的 $O(n)$ 选最大值过程。
1. **第一阶段（建堆）**：对原始无序数组自底向上建大根堆，耗时 $O(n)$。此时堆顶（下标 1）为全局最大值。
2. **第二阶段（循环选最大值并就地固定）**：
   * **对调**：将堆顶最大值与当前堆的最后一个叶子节点互换（最大值就地归位到数组末尾）；
   * **缩容**：逻辑上将堆的大小减 1（排好序的末尾元素不再参与后续堆化）；
   * **修复**：对篡位上来的新根节点执行一次**向下堆化（下沉）**，耗时 $O(\log n)$，选拔出剩余元素中的次大值重登堆顶；
3. **终止**：重复上述过程 $n-1$ 次，直到堆大小缩减为 1。此时整张数组呈**从小到大**完全有序排列。
---
### 核心记忆速记表
| 维度 | 关键特征 |
| :--- | :--- |
| **建堆时间** | $O(n)$ |
| **总排序时间** | 最好、最坏、平均均为严格的 **$O(n \log n)$** |
| **额外空间** | **$O(1)$**（就地交换，原地排序） |
| **稳定性** | **不稳定**（跨越式的父子对调容易打乱相同元素的相对次序） |


## 树的概念之间的关系推导
### 一、 节点数（$n$）与度（$d$）的关系推导
“度”（Degree）就是**一个节点生了几个孩子**。
* 叶子节点的度为 0（记为 $n_0$ 个）；
* 独生子女节点的度为 1（记为 $n_1$ 个）；
* 双胞胎节点的度为 2（记为 $n_2$ 个）；
* 度为 $m$ 的节点记为 $n_m$ 个。
#### 核心推导：数一数整棵树里一共有多少根“树枝”（边数 $B$）？
我们站在整棵树面前，分别用两种视角去数树枝：
1. **向下看（老子生了多少孩子）：**
* 度为 0 的节点伸出 0 根树枝；
* 度为 1 的节点伸出 1 根树枝；
* 度为 2 的节点伸出 2 根树枝；
* 度为 $k$ 的节点伸出 $k$ 根树枝；
* **总树枝数** $B = 0 \times n_0 + 1 \times n_1 + 2 \times n_2 + \dots + m \times n_m$
2. **向上看（每个孩子头上顶着一根树枝认亲）：**
* 整棵树除了唯一的根节点（Root）头上没有树枝，**其余所有节点头顶上都严格连着一根指向老爹的树枝**！
* 所以，总节点数是 $n$，除掉根节点，剩下的 $n-1$ 个节点每个人头上一根线。
* **总树枝数** $B = n - 1$
#### 连立方程（秒杀所有度数题）：
$$n - 1 = 1 \cdot n_1 + 2 \cdot n_2 + 3 \cdot n_3 + \dots + m \cdot n_m$$
又因为总节点数就是各类节点相加：
$$n = n_0 + n_1 + n_2 + \dots + n_m$$
#### 【高频考点】为什么二叉树必有 $n_0 = n_2 + 1$？
把上面的式子收缩到二叉树（最大度为 2）：
* 式一：$n = n_0 + n_1 + n_2$
* 式二：$n - 1 = n_1 + 2n_2 \implies n = n_1 + 2n_2 + 1$
两式相减：
$$(n_0 + n_1 + n_2) = (n_1 + 2n_2 + 1) \implies \mathbf{n_0 = n_2 + 1}$$
**结论**：二叉树中，**度为 0 的叶子节点数，永远比度为 2 的分支节点数恰好多 1 个！** 度为 1 的节点有多少个完全不影响这个结果。
### 二、 高度（$h$）与节点数（$n$）、度（$m$）的关系推导
很多同学记不住高度 $h$ 的范围到底是 $\lceil \log_2(n+1) \rceil$ 还是什么。推导这个只需要在脑海中画出两种**极端形态**：**最瘦的树**和**最胖的树**。
以度为 $m$ 的树（$m$ 叉树）为例：
#### 1. 最瘦形态：每个节点都只有一个单传孩子（退化成一条细竹竿）
* 每一层只有一个节点。
* 高度 $h$ 达到**极大值**：
$$h_{\max} = n$$
反过来，给定高度 $h$，至少需要的节点数：
$$n_{\min} = h$$
#### 2. 最胖形态：满 $m$ 叉树（每一层都生满 $m$ 个孩子，塞到爆炸）
* 第 1 层（根）：$m^0 = 1$ 个
* 第 2 层：$m^1$ 个
* 第 3 层：$m^2$ 个
* ……
* 第 $h$ 层：$m^{h-1}$ 个
根据等比数列求和公式，高度为 $h$ 的树**最多能容纳的节点数**：
$$n_{\max} = 1 + m + m^2 + \dots + m^{h-1} = \frac{m^h - 1}{m - 1}$$
特别地，当 $m = 2$（满二叉树）时：
$$n_{\max} = \frac{2^h - 1}{2 - 1} = 2^h - 1$$
#### 3. 从最胖形态反推最小高度 $h_{\min}$
既然节点数为 $n$ 时最多能填满满 $m$ 叉树，那么：
$$n \le \frac{m^h - 1}{m - 1}$$
对于二叉树（$m=2$）：
$$n \le 2^h - 1 \implies 2^h \ge n + 1 \implies \mathbf{h \ge \log_2(n+1)}$$
因为高度必须是整数，所以向上取整：
$$\mathbf{h_{\min} = \lceil \log_2(n+1) \rceil} \quad \text{或等价写作} \quad \mathbf{\lfloor \log_2 n \rfloor + 1}$$
---
### 三、 完全二叉树的父子节点推导（纯数组模拟二叉树）
大根堆能够不用指针直接用数组跑，全靠这个数学映射。
假设数组下标从 **$1$** 开始：
1. **孩子找爹**：
* 无论你是左孩子还是右孩子，你的父亲节点下标一定是：
$$\text{parent} = \lfloor i / 2 \rfloor$$
2. **爹找孩子**：
* 左孩子下标：$2i$
* 右孩子下标：$2i + 1$
3. **最后一个非叶子节点为什么是 $\lfloor n / 2 \rfloor$？**
* 最后一个叶子节点下标显然是 $n$。
* 这个最底层的末尾小弟，它的父亲就是全树最后一个非叶子节点，它的下标自然就是：
$$\lfloor n / 2 \rfloor$$
* 所以堆化扫描从 $\lfloor n / 2 \rfloor$ 往前倒着走，绝不漏掉一个非叶子节点。
---
### 总结速查口诀
* **树枝总数**：老爹生的孩子总数（$\sum d \cdot n_d$）$=$ 孩子头顶的绳子数（$n - 1$）。
* **二叉树叶子与双亲**：$n_0 = n_2 + 1$（多生双胞胎，叶子就多一个）。
* **树的高矮极值**：最瘦是竹竿（$n = h$），最胖是满树（等比数列求和 $2^h - 1$）。

## 公式速记
### 树的性质与公式速查表
---
#### 1. 节点数与度数（核心方程组）
* **通用边数守恒**：
$$n - 1 = \sum (i \cdot n_i) = 1 \cdot n_1 + 2 \cdot n_2 + 3 \cdot n_3 + \dots + m \cdot n_m$$
* **总节点数**：
$$n = \sum n_i = n_0 + n_1 + n_2 + \dots + n_m$$
* **二叉树必考特例**：
$$n_0 = n_2 + 1$$
*(度为 0 的叶子节点数 = 度为 2 的节点数 + 1)*
---
#### 2. 高度（$h$）、节点数（$n$）与度（$m$）的极值
* **最瘦形态（单支竹竿）**：
$$h_{\max} = n \quad \iff \quad n_{\min} = h$$
* **最胖形态（满 $m$ 叉树）**：
$$n_{\max} = \frac{m^h - 1}{m - 1}$$
* 二叉树特例（$m = 2$）：$n_{\max} = 2^h - 1$
* **最小高度（完全 $m$ 叉树）**：
$$h_{\min} = \lceil \log_m(n(m - 1) + 1) \rceil$$
* 二叉树特例（$m = 2$）：
$$h_{\min} = \lceil \log_2(n + 1) \rceil = \lfloor \log_2 n \rfloor + 1$$
---
#### 3. 完全二叉树的数组下标映射（1-based 下标，总节点数 $n$）
* **父节点下标**：$\lfloor i / 2 \rfloor$
* **左孩子下标**：$2i$（若 $2i > n$，则无左孩子）
* **右孩子下标**：$2i + 1$（若 $2i + 1 > n$，则无右孩子）
* **最后一个非叶子节点下标**：$\lfloor n / 2 \rfloor$
* **叶子节点下标范围**：$\lfloor n / 2 \rfloor + 1 \sim n$
* **度为 1 的节点数（$n_1$）**：
* $n$ 为偶数时：$n_1 = 1$
* $n$ 为奇数时：$n_1 = 0$
* **叶子节点总数（$n_0$）**：
$$n_0 = \lceil n / 2 \rfloor = \lfloor (n + 1) / 2 \rfloor$$

## 节点数和叶子节点关系

对任意有 $n$ 个结点的完全二叉树
- **叶子结点数** = $\lceil n / 2 \rceil$（$n$ 除以 2 向上取整）
- **非叶子结点数** = $\lfloor n / 2 \rfloor$（$n$ 除以 2 向下取整）

## 二叉排序树
一棵二叉排序树要么是一棵空树，要么满足以下三条性质：
左子树上所有结点的值，均小于根结点的值；
右子树上所有结点的值，均大于根结点的值；
它的左、右子树也各自是一棵二叉排序树（递归定义）。
简单记法：左小右大。
## 哈夫曼需要加入虚拟节点个数和添加权值为零的节点个数问题
设真实叶子节点数为 $n_0$，相加生成的内部节点数为 $n_k$。
1.整棵树的总节点数 $N$ 满足：

$$N = n_0 + n_k = n_0 + \frac{n_0 - 1}{k - 1}$$
2.
- **不需要加空节点**：当 $(n_0 - 1) \pmod{k - 1} == 0$。
- **需要加空节点**：当 **$(n_0 - 1) \pmod{k - 1} \ne 0$**。
3.需要添加的空节点（权值为 0）的个数 $x$ 为：
$$x = (k - 1) - ((n_0 - 1) \pmod{k - 1})$$
## 线索二叉树
线索二叉树“形成的链表顺序”以及它的“前驱和后继”，**严格取决于当初线索化时使用的是哪一种遍历方式**。
一般默认是线索二叉树是中序遍历得到的
#### 一个线索二叉树指针的关系
- **指针总数**：
    一棵二叉树有 $n$ 个结点，每个结点都有左、右两个孩子指针域（`lchild` 和 `rchild`），所以整棵树一共有 **$2n$ 个指针**。
- **实指针数（非线索指针）**：
    除根结点外，树中的每一个结点都有且仅有一条来自父结点的边指向它。
    因此，真正指向左、右孩子的非空指针（实指针）共有 **$n - 1$ 个**。
- **线索数（由空指针转化而来）**：
    剩下的所有原本为 `NULL` 的指针，在线索化后都变成了指向前驱或后继的“线索”：
    $$\text{线索数} = \text{指针总数} - \text{实指针数} = 2n - (n - 1) = n + 1$$

## 哈夫曼树的长度问题
哈夫曼树的高度是从零开始的，第一层是零，如果就两层，那么权值是1*叶子节点的树
因此计算加权路径长度 $\sum (w_i \times l_i)$ 时，乘的 $l_i$ 确实是：
- 根节点的孩子：$\times 1$
- 孙子节点：$\times 2$
- 曾孙节点：$\times 3$
