# 新增功能分析：网址路径同步（URL 路由）

> 让「当前打开的文件」反映在浏览器地址栏上，刷新/收藏/分享链接都能直达那个文件。

---

## 一、需求概述

| 诉求 | 说明 |
|------|------|
| 点文件 → 网址跟着变 | 地址栏显示当前文件的路径和名字，如 `http://服务器/#/数据结构/3图/总文件.md` |
| 刷新不丢 | 刷新页面、关掉重开，直接回到之前那个文件，不用重新一层层点 |
| 可分享/收藏 | 收藏某个文件链接，或发给别人，打开直接定位到那个文件 |

**本质**：这是标准的「前端路由」需求。当前项目完全没有路由，`currentPath` 只是内存变量，所以一刷新就回到初始状态——这正是你遇到的现象。

---

## 二、现状分析

| 项 | 现状 |
|----|------|
| 前端路由 | **无**。`main.js` 只 `createApp(App).mount('#app')`，没引入 vue-router |
| 当前文件状态 | `App.vue` 里 `currentPath` 是 `ref('')`，纯内存，刷新即丢 |
| 后端静态托管 | `StaticFiles(html=True)` 挂载在 `/`，返回 index.html |
| 地址栏 | 永远停在 `/`，不随点击变化 |

**结论**：需要给前端加路由能力，让「当前文件」和「网址」双向绑定。

---

## 三、技术选型（核心决策）

### 3.1 用 hash 路由还是 history 路由？

| 方案 | 网址形态 | 后端改动 | 结论 |
|------|---------|---------|------|
| **A. Hash 路由**（`#/路径`） | `http://服务器/#/数据结构/3图/总文件.md` | **零改动**（`#` 后面不发给服务器） | ✅ 推荐 |
| B. History 路由（`/路径`） | `http://服务器/数据结构/3图/总文件.md` | 需要后端加 SPA fallback（任意路径都返回 index.html） | 更「干净」但要改后端 |

**推荐方案 A（Hash 路由）**，理由：

1. **后端完全不用改**——URL 里 `#` 之后的部分是「片段」，浏览器不会把它发给服务器，刷新时服务器仍只收到 `/`，返回 index.html，前端再读 `#` 还原状态。这是 hash 路由最核心的好处，尤其适合你现在「后端已经部署好、不想动」的情况。
2. 实现最简单，甚至**可以不用 vue-router**，自己写十几行代码监听 `hashchange` 就够了。
3. 唯一「缺点」是网址里多个 `#`，但对阅读器这种自用场景完全无所谓。

> 如果你更在意网址「干净」（不要 `#`），可以选 history 路由，但要给后端加一行 SPA fallback。第一版建议先做 hash 路由，简单可靠。

### 3.2 用 vue-router 还是自己写？

| 方案 | 说明 | 结论 |
|------|------|------|
| **A. 自己写 hash 路由** | 监听 `hashchange` + 读写 `location.hash`，约 30 行 | ✅ 推荐（项目只有一个「文件」维度，没必要引入完整路由库） |
| B. 引入 vue-router | 标准方案，但要加依赖、配 routes | 过度设计 |

**推荐 A**：这个阅读器本质上只有一个「状态」需要同步到网址——当前打开的文件路径。自己写 hash 同步，比引入 vue-router 更轻、更可控。

## 四、实现方案

### 4.1 核心思路

把「当前文件路径」变成唯一的真源，和 `location.hash` 双向同步：

```
点击文件 → 写 location.hash = '#/数据结构/3图/总文件.md'  → hashchange 事件 → 打开文件
刷新页面 → 读 location.hash  → 解析出路径 → 自动打开那个文件
```

### 4.2 前端改动（都在 `App.vue`）

**1. 路径 ↔ hash 编解码**（两个工具函数）：

```js
// 文件路径 → hash（注意中文/特殊字符要编码，用 encodeURIComponent 但保留 /）
function pathToHash(path) {
  return '#/' + path.split('/').map(encodeURIComponent).join('/')
}
function hashToPath(hash) {
  const raw = hash.replace(/^#\/?/, '')   // 去掉 '#/' 前缀
  if (!raw) return ''
  return raw.split('/').map(decodeURIComponent).join('/')
}
```

**2. 点击文件时写 hash**：

在 `openFile(item)` 里，打开文件的同时 `location.hash = pathToHash(item.path)`。

**3. 监听 `hashchange`，反向打开文件**：

```js
window.addEventListener('hashchange', () => {
  const p = hashToPath(location.hash)
  if (p && p !== currentPath.value) openByPath(p)
})
```

**4. 初始化时读 hash（恢复上次的文件）**：

```js
onMounted(() => {
  const p = hashToPath(location.hash)
  if (p) openByPath(p)   // 刷新后自动打开上次的文件
})
```

**5. 防循环**：`openFile` 写 hash 会触发 `hashchange`，`hashchange` 又调 `openByPath`。用「路径相同就跳过」的守卫避免重复打开：

```js
// openByPath 里：如果目标路径 === 当前路径，直接 return（防止 hash 回写触发重复加载）
```

### 4.3 后端改动

**无**（hash 路由下，`#` 之后不发送到服务器，`StaticFiles` 已经能正确返回 index.html）。

### 4.4 一个顺带的好处：阅读进度联动

你上一轮已经做了「阅读位置记忆」（存后端）。加上 URL 路由后，它们天然配合：

- 你在手机收藏了 `#/数据结构/3图/总文件.md` 这个链接
- 下次打开 → 自动打开文件 → 自动恢复阅读进度（上一轮的功能）

整个「打开即回到上次位置」的体验就闭环了。

## 五、边界与注意事项

1. **中文/空格路径**：hash 里要 `encodeURIComponent`，读回来 `decodeURIComponent`。否则中文文件名会在地址栏显示成乱码或丢失。
2. **搜索跳转**：搜索定位到某文件时，也应该同步写 hash（这样搜索到的文件也能通过网址直达）。
3. **新建文件**：新建后打开的文件同样写 hash。
4. **hash 太长**：文件路径很长时网址会长，但这是 hash 路由的正常现象，浏览器能处理，不影响功能。
5. **PDF/图片**：PDF 和图片文件同样用路径做 hash，刷新后也能直接打开对应的 PDF/图片查看器。

### 实际落地要点（与方案文档差异）
- 用户要的是 **history 路由**（`/数据结构/3图/总文件.md`，无 `#`），不是 hash 路由。所以后端**加了一行 SPA fallback**（catch-all 返回 index.html），前端用 `history.pushState` 而非 `location.hash`。
- 未引入 vue-router，自写约 40 行（`pathToUrl`/`urlToPath` + `syncUrl` + `popstate` + 初始化读 pathname）。

### 改动文件
- `server/main.py`：静态托管改为 `/assets` mount + `@app.get("/{full_path:path}")` catch-all 返回 index.html
- `web/src/App.vue`：加 history 路由同步逻辑（工具函数 + pushState + popstate + 初始化还原）

### 遇到的坑
1. **SPA fallback 顺序**：`/assets` 静态 mount 必须注册在 catch-all `/{full_path:path}` 之前，否则 JS/CSS 会被兜底成 index.html 导致白屏。
2. **中文路径编码**：pushState 的 URL 里中文按段 `encodeURIComponent`（保留 `/`），读回时 `decodeURIComponent`。
