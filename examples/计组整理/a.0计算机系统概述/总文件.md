# 计算机系统概述 · 总文件

## 一、从源程序到可执行文件

整个过程分为四个阶段：

**1. 预处理阶段**
使用预处理器，把程序中的头文件替换成完整内容，得到一个 hello.i 文件。

**2. 编译阶段**
编译器把 hello.i 文件翻译成汇编语言文件 hello.s。

**3. 汇编阶段**
汇编器把 hello.s 变成机器语言指令，生成可重定位的目标文件 hello.o。

**4. 链接阶段**
链接器把 hello.o 与它依赖的其他目标文件，以及标准 C 库的二进制文件合并。它会扫描所有二进制文件中的函数和变量，把代码中原本空缺、模糊的函数调用位置，替换为该函数在最终内存空间中的真实物理地址或相对偏移量，从而把零散的二进制零件组装成一个可以独立运行的可执行文件。

链接阶段内部又分成两个动作：

**动作 A：零件合并（Section Merging）**
链接器先把 hello.o 的二进制代码、其他模块的二进制代码，以及 C 库（如 libc.a）里被用到的函数的二进制代码，全部收集过来。它把所有文件的代码段（存放机器指令的地方）拼成一个巨大的、连续的二进制代码块。这时候，所有函数在内存中的最终排布位置就被固定下来了。

**动作 B：地址修正（Relocation，重定位）**
这对应「替换为实际指向函数代码的指针」这一步。在汇编阶段刚结束时，hello.o 内部如果调用了 printf，由于汇编器不知道 printf 会被拼在内存的哪个角落，生成的机器码里只能留一个占位符。在 x86 汇编底层，这表现为一条跳转指令后面跟着几个零，比如 `e8 00 00 00 00`，其中 e8 是 call 指令的机器码，后面四个字节的零就是等待填入的「指针」。到了链接阶段，链接器把拼图完成后算出来 printf 的真实地址，于是直接走到 hello.o 留下的空位上，把那四个字节的零改写为真实地址引用，比如改写成 `e8 4c 10 40 00`。

## 二、计算机的性能指标与公式

**基本定义**

| 指标 | 含义 |
|---|---|
| 时钟周期 | CPU 工作的最小时间单位 |
| 主频 | 时钟周期的倒数，即每秒包含的时钟周期数 |
| CPI | 执行一条指令所需的时钟周期数 |
| IPC | 每个时钟周期执行的指令数 |
| 平均 CPI | 平均时钟周期数 |
| IPS | 每秒执行的指令数 |

**核心公式**

- IPS = 主频 ÷ 平均CPI

- CPU执行时间 = CPU时钟周期数 ÷ 主频
  = （指令条数 × CPI）÷ 主频
  = 指令条数 × CPI × 时钟周期

- MIPS = 指令条数 ÷ （CPU执行时间 × 10的6次方）
