# 内存管理 · 总文件

# 内存管理概念

## 一、三种装入情况

### 1. 绝对装入（出厂定死）

- **核心动作：** 编译代码时，就写死了物理内存地址。
- **特点：**
    - **单道专享**：只适合单道系统（当时内存里就它一个程序，位置绝对固定）。
    - **僵硬死板**：程序在内存里的位置一点都不能变；如果换个机器或者位置变了，必须**重新编译**。
### 2. 静态重定位（入住定死）

- **核心动作：** 编译时用相对地址（从 0 开始）；**装入内存的那一瞬间**，装入程序把所有地址一次性修改为实际物理地址。
- **特点：**  
    - **连续且一次性**：必须给程序分配一块**完整连续**的物理空间，且必须全部装入才能运行。
    - **中途不能挪动**：一旦住下，地址就被“焊死”改写了，运行期间**不能在内存中移动**，也不能换出到外存再换回不同位置。
### 3. 动态重定位（随用随算）

- **核心动作：** 编译和装入时都不改地址；**CPU 真正要执行某条指令的瞬间**，由硬件（MMU/重定位寄存器）动态查表计算出物理地址。
- **特点：**
    - **灵活可挪动**：程序在内存里可以随时搬家（如内存碎片整理、换入换出），只需要改一下寄存器或页表。
    - **支持不连续与按需调入**：现代分页/分段管理的基础，程序可以被打散存放在内存各个角落，甚至不用全部装入内存就能跑（虚拟内存）。

## 二、三种连续分配情况
连续分配管理方式是指**为一个用户程序分配一个连续的内存空间**。主要分为以下三种方式：
### 1. 单一连续分配（Single Contiguous Allocation）

- **原理：** 内存被简单划分为两块——**系统区**（给 OS 内核使用，通常在低地址）和**用户区**（给用户程序使用）。
- **特点：** 
    - **单道专享**：内存中**同一时刻只能有一道用户程序**运行。
    - **实现极简**：无需复杂的内存保护与硬件转换机制。
    - **浪费严重**：存在极大的**内部碎片**（大房子只住一个人，剩下的空间全浪费了）。
### 2. 固定分区分配（Fixed Partitioning）

- **原理：** 在系统启动时，把用户内存空间预先划分为**若干个固定大小的分区**（每个分区大小可以相等，也可以不等），每个分区只装入一道作业。
- **特点：**
    - **支持多道**：最早期的多道程序内存管理技术。
    - **缺乏灵活性**：分区大小和数量事先定死，程序太大装不下，程序太小又占满整个分区。
    - **内部碎片严重**：只要程序大小小于所在分区的容量，分区内剩余的空间就无法被他人利用（产生**内部碎片**），但**没有外部碎片**。
### 3. 动态分区分配（Dynamic Partitioning，又称可变分区）

- **原理：** 事先不划分分区，而是在进程装入内存时，**根据进程实际需要的大小动态划出一块刚好够用的空间**给它。
    
- **特点：**
    - **按需分配**：分配时刚刚好，因此**没有内部碎片**。
    - **产生外部碎片**：频繁的分配和回收后，内存中会散落许多**容量太小、无法容纳任何新进程的空闲小碎块**（称为**外部碎片**）。
    - **需要算法支持**：需要空闲链表/空闲表来记录空闲块，并借助放置算法挑选空闲区（如 **首次适应 FF、最佳适应 BF、最坏适应 WF、邻近适应 NF**）。
    - **可用紧凑技术消除碎片**：可以通过“内存紧凑（拼凑）”将已占用的空间向一端挪动来合并外部碎片，但这需要**动态重定位**的硬件支持。
### 三种连续分配方式对比总结

|**分配方式**|**支持多道**|**内部碎片**|**外部碎片**|**内存利用率**|**划分时机**|
|---|---|---|---|---|---|
|**单一连续分配**|否（仅单道）|**严重**|无|极低|预先固定|
|**固定分区分配**|是|**严重**|无|较低|预先固定|
|**动态分区分配**|是|**无**|**严重**（需紧凑技术）|较高|运行时动态划分|

> **考点辨析（内部碎片 vs 外部碎片）：**
> - **内部碎片**：已经分给了某个进程，但进程**用不完**而浪费的空间（分区内部）。
> - **外部碎片**：太小而**无法分配给任何进程**的空闲零散内存（分区之间）。

## 三、四种回收情况

### 情况一：只有前（上）邻区是空闲的

- **物理状态：** `[空闲区 A] + [要回收的分区] + [其他进程占用的分区]`

- **处理动作：** **向上合并**

    1. 将回收区直接合并到前一个空闲区 A 中。
    2. **修改前邻区项：** 起始地址保持不变，大小增加为：
$$\text{新大小} = \text{空闲区 A 的原大小} + \text{回收区大小}$$
        
    3. 空闲分区表/链的**总节点数量不变**。

### 情况二：只有后（下）邻区是空闲的

- **物理状态：** `[其他进程占用的分区] + [要回收的分区] + [空闲区 B]`
- **处理动作：** **向下合并**  
    1. 将回收区合并到后一个空闲区 B 中。  
        
    2. **修改后邻区项：** 
        - **起始地址改为回收区的起始地址**（因为回收区地址更靠前）。
        - 大小增加为：
            $$\text{新大小} = \text{空闲区 B 的原大小} + \text{回收区大小}$$
            
    3. 空闲分区表/链的**总节点数量不变**。
### 情况三：前后（上下）邻区全都是空闲的

- **物理状态：** `[空闲区 A] + [要回收的分区] + [空闲区 B]`
- **处理动作：** **三合一合并**
    1. 将前邻区 A、回收区、后邻区 B 三者合并为一个超大空闲区。

    2. **保留前邻区并修改：** 起始地址依然是空闲区 A 的起始地址，大小变为：
$$\text{新大小} = \text{空闲区 A 大小} + \text{回收区大小} + \text{空闲区 B 大小}$$
        
    3. **删除后邻区：** 在空闲分区表/链中**删掉后邻区 B 的对应节点**（因为已被合并到 A）。
    4. 空闲分区表/链的**总节点数量减 1**。
### 情况四：前后（上下）邻区全都在被使用（都不空闲）

- **物理状态：** `[其他进程占用] + [要回收的分区] + [其他进程占用]`
- **处理动作：** **独立建新表项**
    1. 没有任何相邻的空闲区可以合并。
    2. 在空闲分区表/链中**新建一个节点**，记录该回收区的起始物理地址和大小。
    3. 按照当前的空闲链管理规则（如按地址递增顺序）插入到合适的位置。
    4. 空闲分区表/链的**总节点数量加 1**。
### 4 种情况速记表

|**相邻空闲情况**|**合并对象**|**起始地址变化**|**占用大小变化**|**空闲表节点数变化**|
|---|---|---|---|---|
|**仅有上邻**|并入上邻区|不变|增加回收区大小|**不变**|
|**仅有下邻**|并入下邻区|**变为回收区起始地址**|增加回收区大小|**不变**|
|**上下均邻**|三者合并为一个|保持上邻区起始地址|加上回收区和下邻区大小|**减 1**（删去下邻区表项）|
|**上下均无**|不合并|记录回收区起始地址|记录回收区大小|**加 1**（新建表项）|
## 四、四种适应算法

| **空闲分区的排列顺序**                    | **查找时的搜索策略**             |                                          |     |     |
| -------------------------------- | ------------------------ | ---------------------------------------- | --- | --- |
| **首次适应算法 (First Fit, FF)**       | **按地址递增顺序排列**            | **每次都从链表头（地址最低处）** 开始向后找，遇到第一个满足大小的就分配。  |     |     |
| **临近适应 / 循环首次适应 (Next Fit, NF)** | **按地址递增顺序排列**（与 FF 完全相同） | **从上次找到的空闲分区位置开始** 继续向后循环查找（到达链表尾则绕回表头）。 |     |     |
| **最佳适应算法 (Best Fit, BF)**        | **按容量大小递增顺序排列**          | 每次从链表头开始找，**遇到的第一个**就是“大于等于所需尺寸中最小的那块”。  |     |     |
| **最坏适应算法 (Worst Fit, WF)**       | **按容量大小递减顺序排列**          | 每次直接看**链表头的第一个分区**（因为第一项就是当前全系统最大的一块）。   |     |     |
1.首次适应算法那和最近适应算法是地址从小到大找
最佳是容量从小到大
最坏是容量从大到小

## 五、内外部碎片的各种管理模式分析

|**连续性**|**具体管理模式**|**采用的装入方式**|**核心硬件支持**|**碎片特征**|
|---|---|---|---|---|
|**连续分配**|**单一连续分配**|绝对装入 / 静态重定位|无 / 简单界限寄存器|严重内部碎片（单道程序）|
||**固定分区分配**|**静态重定位装入**|无（软件改写地址）|**只有内部碎片**（大分区装小进程）|
||**可变分区分配***(动态分区)*|**动态运行时装入**|**重定位寄存器 + 界限寄存器**|**只有外部碎片**（需内存紧凑消除）|
|**离散分配**|**基本分页**|**动态运行时装入**|页表基址寄存器 + TLB + 地址拼接|**只有内部碎片**（进程尾页装不满）|
||**基本分段**|**动态运行时装入**|段表基址/长度寄存器 + TLB + 加法器|**只有外部碎片**（段与段之间）|
||**段页式管理**|**动态运行时装入**|段表/页表寄存器 + TLB + 拼接逻辑|**只有内部碎片**（每个段的尾页）|
|**虚拟内存**|**请求分页/请求分段**|**动态运行时装入***(按需调页/调段)*|包含缺页中断机构、状态位硬件|同对应离散模式|
1.连续分配的那三种就是三种装入模式的具象化，
2.动态分区发展出了离散分配的几种，段页式是因为是逻辑分段，内部还是页所以有碎片

## 六、二级页表实现逻辑
### 一、 核心概念与物理结构（页表在物理内存中怎么存？）
以 **32 位逻辑地址空间（4GB）**、**页面大小为 4KB** 的系统为例：
1. **一级页表（页目录表）**
* **数量与大小**：全进程只有 **1 个**，独占 1 个物理页框（**4KB**）。
* **内部结构**：划分为 1024 项（4KB / 4B = 1024 = 2^10），每项占 **4B（32位）**。
* **高 20 位**：指向某个**二级页表的物理页框号**（末尾补 12 个 0 即为物理起始基地址）。
* **低 12 位**：权限与状态标志位（存在位 P、读写权限 R/W、访问位 A 等）。
2. **二级页表（分级页表）**
* **数量与大小**：按需分配（最多 1024 个），每个二级页表同样占 1 个物理页框（**4KB**）。
* **内部结构**：每个二级页表包含 1024 项，每项占 **4B（32位）**。
* **高 20 位**：指向**真正存放数据的物理页框号**。
* **低 12 位**：权限与状态标志位（含修改脏位 D 等）。
3. **内存存放特点（关键点）**
* 一级页表、二级页表和真实数据**共享物理内存**，都以 4KB 为单位打散存放在任意空闲页框中。
* 二级页表**不必全部预先创建**，进程用到哪部分虚拟空间才动态建立对应的二级页表，大幅节省物理内存。
### 二、 地址转换与寻址流程（10 + 10 + 12 是怎么跑通的？）
CPU 发出的 **32 位虚拟逻辑地址** 在硬件逻辑上被自动切分为三段：
`[ 一级页号 (10位: 31~22) ] [ 二级页号 (10位: 21~12) ] [ 页内偏移量 (12位: 11~0) ]`
1. **定位一级页表项（定位到“章”）**
* CPU 读取控制寄存器（**CR3**）获取该进程**一级页表的物理基地址**。
* 以虚拟地址的 **前 10 位（一级页号，0~1023）作为数组下标**：一级页表项物理地址 = CR3 基地址 + (前10位页号 × 4B)。
* 从该项的高 20 位读出目标**二级页表的物理基地址**。
2. **定位二级页表项（定位到“节”）**
* 以虚拟地址的 **中间 10 位（二级页号，0~1023）作为数组下标**：二级页表项物理地址 = 二级页表物理基地址 + (中间10位页号 × 4B)。
* 从该项的高 20 位读出目标**真实数据页的物理页框号**。
3. **拼接生成最终物理地址（定位到“具体字节”）**
* 取出数据页的物理基地址，直接加上虚拟地址的 **最后 12 位（页内偏移量，0~4095）**：最终物理地址 = 数据页物理基地址 + 页内偏移量。
* CPU 沿物理总线精准读写对应字节。
### 三、 核心本质：为什么要设计两级页表？
* **单级页表的痛点**：全表必须占用 2^20 × 4B = 4MB **连续**物理空间，小进程也要硬吃 4MB，且不能分散存放。
* **两级页表的精妙之处**：
1. **离散存储**：一级页表记录的是二级页表的 **20 位物理地址**，使得二级页表可以像数据页一样**分散存放在物理内存的任何空闲页框中**，无需连续。
2. **按需分配**：不需要一次性把 1024 个二级页表全部建好装入，未使用的地址空间不生成二级页表。
* **总结代价与收益**：**多了一次内存查表访问（用寻址时间换空间）**，换来了页表本身的**离散存放能力**与**极高的物理内存利用率**。

## 七、两级页表的物理结构与地址转换

### 一、物理存储布局（20 + 12 结构，真实视角）

以 4GB 内存、页面大小 4KB 为例：

- 首先，物理上计算机把一个 4KB 分给一级页表，分为 1024 块，每块 4B。每块的前 20 位是指向二级页表的地址，后 12 位是标志位，表明权限读写、是否优先。
- 然后，再把 1024 个 4KB 分给二级页表，结构一样，每页分 1024 块，每块前 20 位是指向真实存储数据的地址，后 12 位是标志位。
- 剩余的「4GB 减去 4MB 再减去 4KB」的空间，就是完全用来放数据的。

### 二、地址转换（10 + 10 + 12 抽象视角）

CPU 得到的是 10 + 10 + 12 的结构，转换过程如下：

1. 先根据第一个 10 位，去一级页表找对应的页号，用这 10 位页号得到二级页表的 20 位地址。
   这里容易产生一个疑惑：为什么不让二级页表像一级页表一样固定放置，这样计算机就可以通过 10 位页号直接找到二级页表，而不是通过 20 位物理地址？答案是——如果那样做，还要一级页表干什么。一级页表的作用，就是让二级页表能够分散放置，用一点寻址时间，换来了空间利用率的提高。
2. 再通过 20 位地址找到二级页表，然后通过中间的 10 位，得到真实存放数据的块号地址。
3. 找到它之后，加上偏移量，就得到了真实的、精确到字节的要访问的地址。

### 三、关键建模

1. 计算机为每一个进程都分配了至少一个一级页表和一个二级页表，也就是保底 8KB。
2. 段页式就是：首先分为几个大段，然后每个段再分为小页。

## 九、各部分组成
可以直接记这套**一般规律**：
### 1. 逻辑地址空间
* **CPU逻辑地址位数**决定**逻辑地址空间大小**
* \(n\) 位逻辑地址 → 逻辑空间 \(2^n\) 个地址
* 例如 32 位 → \(2^{32}\) B = 4GB
### 2. 逻辑地址组成
分页系统中：
$$
\boxed{\text{逻辑地址}=\text{逻辑页号}+\text{页内偏移}}
$$
多级页表时，逻辑页号还可以继续拆：
$$
\boxed{\text{逻辑页号}=\text{页目录号}+\text{页表号}+\cdots}
$$
所以：
> **页目录号、页表号、页内偏移，都是逻辑地址的组成部分。**

页目录号页页表号也叫一级页表和二级页表（统称逻辑页号）
### 3. 页表项
页表项不是逻辑地址的一部分，而是**页表中的一条记录**。
通常包含：
$$
\boxed{\text{物理页框号}+\text{标志信息}}
$$
其中标志信息包括有效位、权限位、访问位等。
### 4. 地址转换的核心
本质就是：
$$
\boxed{\text{逻辑页号}\rightarrow\text{物理页框号}}
$$
然后：
$$
\boxed{\text{物理地址}=\text{物理页框号}+\text{页内偏移}}
$$
### 5. 几个大小不要混
* **逻辑地址位数** → 决定逻辑空间大小
* **页内偏移位数** → 决定页面大小
* **页表号/页目录号位数** → 决定一个页表能索引多少项
* **页表项大小** → 决定每个页表项占多少空间
* **页表项大小 ≠ 逻辑地址大小**，两者没有必然关系。
## 十、逻辑地址产生和二级页表产生的时间
### 1. 逻辑地址的产生时机
* **静态部分（代码段、数据段）**：在 **编译/链接阶段（Link Time）** 生成可执行文件（ELF/PE）时确定，此时程序还在硬盘上。
* **动态部分（动态库 .so/.dll、堆栈、mmap）**：在 **程序装载或运行时（Load/Runtime）**，由动态链接器或内核在虚拟内存规划（VMA 账本）中分配一段空闲的逻辑地址区间。
---
### 2. 一二级页表结构的创建时机
* **一级页表（页目录）**：在 **进程创建时（如 `fork` / `exec`）** 由操作系统分配并初始化，其物理基地址存入 PCB，并在进程切换时载入 CPU 寄存器（如 CR3）。通常常驻内存。
* **二级页表（具体页表）**：**按需动态创建**。初始时只有少量或全为空；当访问某个地址范围发现对应二级页表不存在时，操作系统才在主存中分配一个物理页作为二级页表。
---
### 3. 二级页表项填入数据（物理映射）的时机
* **时机**：**真正执行访存指令触发「缺页中断」时（Demand Paging 按需调页）**。
* **过程**：
1. 首次访问某逻辑地址，MMU 查表发现 `Valid = 0`，抛出缺页异常。
2. 操作系统分配一个空闲物理页框，将硬盘（程序文件或 Swap 交换区）中的数据读入该页框。
3. 操作系统将**物理页框号**写入二级页表项，并将 **`Valid` 位置为 1**。
* **命中与复用**：初次访问必然发生强制缺页（冷启动）；一旦填表完成，后续基于**局部性原理**（循环、频繁调用、同页内相邻数据）直接命中，无需再查外存。




# 虚拟内存管理


## 十一、内存分配策略
1. **  
    调入策略**：**预调页（一次性调入 / 预先分配）** vs **请求调页（按需调入 / 动态分配）**
2. **分配与置换范围**：**固定分配（分配给进程的物理块数固定）** vs **可变分配（分配给进程的物理块数动态调整）** + **局部置换（只能换自己的页）** vs **全局置换（可以抢占其他进程或空闲池的页）**
在虚拟存储器管理中，**固定分配/可变分配**与**局部置换/全局置换**的 4 种理论组合中，**实际可行的组合恰好有 3 种**（“固定分配全局置换”在逻辑上矛盾，因为一旦允许全局置换，其他进程抢了你的块，你的分配块数就无法固定，所以该组合不存在）。
### 三种内存分配与置换策略组合特点

|**策略组合**|**核心机制**|**优点**|**缺点**|**典型应用场景**|
|---|---|---|---|---|
|固定分配局部置换_)_|• 为每个进程预先分配**固定数量**的物理页框，整个运行期不变。• 缺页时**只能置换该进程自己内部**的某一页。|• 实现简单，进程之间互不干扰。• 某个进程频繁缺页不会连累其他进程。|• 物理块数难以预先精准估计：给多了浪费，给少了容易频繁缺页甚至引发**抖动/颠簸（Thrashing）**。|系统对隔离性要求高、各进程内存需求已知的简单系统。|
|可变分配全局置换_(_|• 进程初始分配一定物理块，系统维护一个**全局空闲物理块池**。• 缺页时，优先从全局空闲池拿块；若空闲池耗尽，**操作系统可从任意进程中挑一页置换出来**。|• 最容易实现，全局动态调配物理内存，灵活性极高。• 物理内存利用率高。|• 进程间互相抢夺物理块，可能引发多米诺骨牌效应（一个进程缺页导致偷走别人的页，进而引发别人也缺页），容易造成**系统抖动**。|多数通用操作系统的基础实现（实现简单、适应性强）。|
|可变分配局部置换**|• 为进程分配一定物理块，缺页时**只换自己的页**。• 操作系统通过监控**缺页率（PFF）或工作集（Working Set）**动态增减该进程的总物理块数。|• 兼具**高度灵活性**与**强隔离性**，能根据进程实际活跃需求动态调控，有效抑制系统抖动。|• 操作系统需要持续监控每个进程的缺页频率或工作集窗口，**系统开销与算法实现复杂度较高**。|追求极致性能与稳定性的现代通用操作系统（如配合工作集模型的内存管理器）。|

## 十二、外存替换策略
1. **对换区空间充足时**：
    - 进程运行前，将与该进程相关的所有数据（代码段、数据段）从**文件区全部拷贝到对换区**。
    - 运行期间的所有换入、换出操作**全部在对换区进行**（利用对换区连续分配、速度快的优势）。
2. **对换区间紧张时**：
    - **只读的代码/文件部分**：换入来自**文件区**；换出时直接丢弃，不占对换区。
    - **会修改的堆/栈/数据部分**：换出与再次调入全部走**对换区**。
3. **UNIX / Linux 现代方式**：
    - 代码段、动态库直接由**文件区**按需调入，换出时直接丢弃重读。
    - 运行过但换出的页面存放在兑换区
    - 只有真正的匿名页（堆、栈等动态数据）在发生置换时才使用**对换区**。

## 十三、工作集和抖动关系

根据**局部性原理**，进程在某一段时间内访问的页面集合通常是高度集中的。
- **工作集窗口大小（​）**：一个时间窗口参数，表示最近访问的 ​ 次页面。
- **工作集 ​**：在时刻 ​ 时，进程在最近的 ​ 次内存访问中所访问过的**不同页面集合**。
#### 极简实例：
假设某个进程的页面访问序列为：
`... 2, 3, 5, 2, 3, 2, 4, 3, 4`，当前刚好停在最后一个 `4`（时刻 ​）。
- 如果设定窗口大小 ​（看最近访问的 4 次）：
    - 最近 4 次访问的序列是：`2, 4, 3, 4`
    - 包含的不同页面为：`{2, 3, 4}` 
    - **此时的工作集大小 ​**。
- **含义**：如果操作系统当前给这个进程分配的物理块数**小于 3**，这个进程就会立刻因为频繁缺页而陷入卡顿。
## 十四、时钟算法展示

- Clock（时钟）算法的本质是 **“用低成本模拟 LRU”**。
  LRU（最近最少使用）性能极好，但每次访存都要移动双向链表或记录时间戳，硬件开销太大。Clock 算法通过一个**循环链表（表盘）加一个指针（时针）**，配合页表里的标志位，轻松实现了类似 LRU 的效果。
 ### 1. 简单的 Clock 算法（NRU，最近未使用）
  #### 核心机制
  - **标志位**：每个页面只有一个 **访问位（A，Access Bit）**。
    - 页面被访问（读/写）时，**硬件自动将 A 置为 1**。
    - 页面调入内存时，A 初始化为 1。
  - **数据结构**：所有在内存中的物理页排成一个**循环单向链表（像钟表的表盘）**。
  - **指针**：一个类似时针的指针，初始指向第一个物理块。
  #### 置换规则（给一次机会原则）
  当发生缺页需要置换时，指针顺时针旋转检查当前指向的页面：
  1. **若当前页 $A = 0$**：说明最近没被用过，**直接选它淘汰**。新页换入该位置，并将新页的 $A$ 置为 1，**指针顺时针移动到下一位**，结束置换。
  2. **若当前页 $A = 1$**：说明最近用过，给它一次“免死机会”，**将它的 $A$ 清零（置为 0）**，指针顺时针移一个页面继续检查。
  3. **循环往复**：最坏情况下，指针转完一整圈把所有页面的 $A$ 都清成 0 后，在第二轮必然能找到一个 $A=0$ 的页面淘汰。
  > **极简记忆**：看到 1 就降成 0 并放过，看到 0 就直接踢掉，指针移到下一个​
  ### 2. 改进型 Clock 算法（考虑修改代价）
  #### 为什么需要改进？
  简单的 Clock 算法只看了“访问过没有”，没看“被修改过没有”。
  - 如果淘汰一个**没修改过的页（干净页）**：不需要写回外存，直接覆盖即可，**I/O 开销为 0**。
    ​
  - 如果淘汰一个**被修改过的页（脏页）**：必须把数据写回外存磁盘，**多一次极慢的磁盘写 I/O**。
    ​
  因此，改进型 Clock 优先淘汰“没访问过 且 没修改过”的页面。
  #### 核心状态组合 $(A, M)$
  每个页面使用两个标志位：**(访问位 A, 修改位 M)**。共有 4 种组合，优先级从高到低（优先淘汰级别高的）：
  1. **$(0, 0)$**：最佳淘汰目标（最近没访问，也没修改，开销最小）。
  2. **$(0, 1)$**：次佳淘汰目标（最近没访问，但被修改过，需要写回磁盘）。
  3. **$(1, 0)$**：较差目标（最近访问过，但没修改）。
  4. **$(1, 1)$**：最差目标（最近又访问又修改，最活跃）。
### 3. 改进型 Clock 算法的四轮扫描规则（做题核心）
  当发生缺页需要置换时，指针最多经历 **4 轮扫描**：
  ```
  第 1 轮扫描 (找最佳 0,0)
    └─ 寻找 (0,0) 的页面
    └─ 找到则淘汰；【不修改任何标志位】
    └─ 若没找到，进入第 2 轮
  第 2 轮扫描 (找次佳 0,1，同时给所有访问过的页面清零)
    └─ 寻找 (0,1) 的页面
    └─ 找到则淘汰；
    └─ 经过的所有页面的【访问位 A 置为 0】(修改位 M 保持不变)
    └─ 若没找到，进入第 3 轮
  第 3 轮扫描 (重复第 1 轮)
    └─ 寻找 (0,0) 的页面
    └─ 找到则淘汰；【不修改任何标志位】
    └─ 若没找到，进入第 4 轮
  第 4 轮扫描 (重复第 2 轮，必然能找到)
    └─ 寻找 (0,1) 的页面，找到直接淘汰。
  ```
### 4. 关键做题细节避坑
1. **指针停在哪？**
   置换完成后，新页写入腾出的物理块，其状态设为 $(1, 0)$（若只是读入）或 $(1, 1)$（若是写入）。**指针必须停留在被置换位置的下一个位置**。
2. **命中时的标志位变化**：
   如果访问的页面已经在内存中（命中）：
   - 读操作：将该页的 $A$ 置为 1。
   - 写操作：将该页的 $A$ 和 $M$ 都置为 1。
   - **命中时指针绝对不移动**。
3. **最多转几圈？**
   最多扫描 4 轮（即指针最多转 2 整圈），必然能找到淘汰页。
## 十五、页回收和页框回收

### 1. 两者的核心本质区别

|**对比维度**|**页面置换 / 回收页（Page Replacement）**|**页框回收 / 物理内存回收（Page Frame Reclaim）**|
|---|---|---|
|**视角层次**|**进程视角（虚拟内存）**|**操作系统内核全局视角（物理内存）**|
|**回收对象**|**页（Page，虚拟地址映射的数据）**决定把哪个进程的哪部分数据踢到外存。|**页框（Page Frame，物理内存条上的格子）**清空物理块并将其归还给系统空闲链表。|
|**触发时机**|通常在进程**发生缺页且分配配额已满**时被动触发。|系统**全局空闲物理内存低于水位线（Watermark）**时由内核主动触发。|
|**终极目标**|为当前进程腾出 1 个槽位装入新数据。|维持整机物理内存的健康水位，防止系统发生 OOM（内存耗尽崩盘）。|
### 2. 页框回收的核心考点（408 / 期末重点）
在操作系统考试和内核机制中，页框回收主要考查以下 4 个核心知识点：
#### ① 物理内存管理算法：伙伴系统（Buddy System）的合并回收
- **考点**：物理页框在分配和释放时，如何避免外部碎片？
- **核心规则**：
  - 系统按 $2^k$ 个连续页框（页块）进行管理。
  - **回收时**：当释放一块大小为 $2^k$ 的页框时，操作系统检查其互为“伙伴”（Buddy）的相邻块是否也空闲。
  - **递归合并**：如果伙伴也是空闲的，立即将它们合并为一个 $2^{k+1}$ 大小的更大连续页块，挂入上一级空闲链表。
#### ② 水位线机制（Watermark）与内核守护线程
- **考点**：操作系统不是等物理内存彻底为 0 才去回收页框，而是通过**高低水位线**平滑控制（如 Linux 的 `kswapd` 守护进程）。
  - **高水位线（High）**：内存充足，内核守护进程休眠。
  - **低水位线（Low）**：空闲页框不足，**后台唤醒 kswapd 异步回收页框**（此时用户进程不卡顿）。
  - **最小水位线（Min）**：内存严重紧缺，触发**直接同步回收（Direct Reclaim）**，阻塞所有申请内存的进程，甚至触发 **OOM Killer** 强杀消耗内存最大的进程。
#### ③ 区分两类页框的回收代价
- **文件页（File-backed Page Frame）**：
  - **干净页（Clean）**：直接释放页框，修改页表 `Valid=0`，**开销为 0**（无需写磁盘）。
  - **脏页（Dirty）**：先异步刷回文件区（Page Cache 回写），再释放页框。
- **匿名页（Anonymous Page Frame，堆/栈）**：
  - 必须先写入**外存对换区（Swap）**，才能将该物理页框清空释放。
#### ④ 进程终止（Exit）时的页框批量回收
- 当一个进程正常结束或异常崩溃（`exit` / `SIGSEGV`）时：
  - 操作系统读取其 PCB，遍历其页表。
  - 释放该进程占用的**所有用户态物理页框**。
  - 释放该进程占有的**多级页表本身所占的物理页框**。
  - 释放 PCB、内核栈等内核数据结构。
  - 将这些物理页框全部标记为空闲，合并回伙伴系统的空闲链表中。
### 3.回收目的
* **根本矛盾**：物理内存条是有限的，而各个进程申请的虚拟空间是巨大的。
* **回收逻辑**：把“长时间不活跃的冷数据”**从物理页框中驱逐出去，将宝贵的物理页框收回全局池子，转让给**“当前正在活跃计算的进程”使用。



## 十六、普通IO和内存映射文件区别


|**对比维度**|**普通 I/O（read / write）**|**内存映射文件（mmap）**|
|---|---|---|
|**访问方式**|通过系统调用 API（流式读写，需指定偏移量和缓冲区）|通过指针直接进行内存读写（指针寻址，像访问数组一样）|
|**数据拷贝次数**|**2 次拷贝**：磁盘 ​ Page Cache（DMA），Page Cache ​ 用户态 `buf`（CPU）|**1 次拷贝（零拷贝）**：磁盘 ​ Page Cache（DMA），虚拟内存直接映射到该物理页|
|**上下文切换**|每次读写都需要陷入内核态（`read`/`write` 系统调用）|仅在初次缺页时陷入内核态，后续读写全在用户态完成|
|**适用场景**|顺序读写、小数据量读写、网络 Socket 流操作|超大文件随机访问、进程间高效共享内存、动态库加载|
