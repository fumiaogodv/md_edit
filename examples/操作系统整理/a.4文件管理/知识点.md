# 文件管理 · 知识点

## 一、文件与目录基础

1.文件控制块就是 FCB。

2.目录文件存放的信息是：该目录中所有子目录和数据文件的目录项。

3.索引节点本身也是一个表，放的是文件的名字和物理位置的映射关系。

4.索引节点瘦身的目的：为了在一个磁盘块里放下更多的 FCB，就把原来「一项很多数据」改为「名字 + 指向别的数据的指针」。

5.一个文件一个 FCB，通常对应一个目录项，目录项 = 文件名 + 指向 FCB 的指针；特殊情况是使用硬链接，一个文件对应两个目录项、一个 FCB。

6.树形目录是从当前路径开始查找。

7.顺序检索法得到的是逻辑地址。

8.「不好分类」的意思是：只能允许两个文件夹嵌套，也就是目录深度只能是 2。

9.串结构与顺序结构的区别：串结构中，关键字和实际物理上的第 i 个不一样，所以不能快速找到某一个关键字；而顺序结构中，第 i 个关键字和物理上起始地址的第 i 个是一致的。

## 二、文件的物理结构（分配方式）

10.物理结构是：顺序分配、链式分配、索引分配；其中链式分配不能实现随机存取。

11.链接分配默认是隐式的。

12.对于链接分配方式，一个表项的簇号放在前一个表项的末尾位置。

13.FAT 文件分配表是全磁盘空间对应一个大表。

14.把链接的结构组成一个表，就实现了随机访问。

15.快速随机存取时，连续结构比索引结构效果好：连续结构一次 IO，索引结构两次 IO 以上。

16.对于混合索引分配，它只会访问当前索引对应的一二级索引，不会从直接块一个一个试。

17.一个文件的索引节点只有一个，那些一级索引、直接地址项都是索引块，不是索引节点。

18.文件的索引结构放在索引节点里。

19.文件块 = 磁盘块 = 数据块。

## 三、索引节点与链接

20.如果 a 硬链接 b，那么 a 和 b 的索引节点是一样的，但文件描述符不一样，各自指向自己用户打开文件表中的一项。

21.可以这样理解：Inode 就是房间里同一份文档（客观存在，只有一份）；文件名 a、b 就是贴在门上的两块不同门牌号（指引到同一个房间）；描述符 a1、b1 就是发给两个人的两张独立借阅证（各拿一张，用来记录自己读到了第几页）。

22.如果 a 软链接了 b、又硬链接了 c，那么删除 a 之后，b 和 c 的引用计数值都还是 1；虽然 b 指向的文件没了，但这个指向关系还在。

23.软链接和硬链接的那个计数器，只和当前访问文件的硬链接数目一致，不管软链接的源文件是否被删除。

24.删除目录中文件 F 的目录项，等价于删除文件；释放 F 的索引节点中占用的内存空间，等价于关闭文件。

## 四、文件操作（系统调用）

25.read 系统调用不需要文件名字，只需要文件描述符，而文件描述符是 open 系统调用生成的。

26.open 调用不需要文件描述符，需要文件名字。

27.关于用 FCB 找文件访问磁盘次数的计算：先算出 FCB 和每个磁盘个数的关系，然后算出有 n 个磁盘放 FCB，得到二分之 n 次，这是得到 FCB 地址的次数；还要加一，得到从 FCB 中获取这个文件索引节点的次数；如果是读入文件的数据，那还要加二。

## 五、文件存储空间管理

28.文件存储空间管理的算法，跟内存管理的那些算法很像。

29.位示图写成二维的，是因为总线的条数关系，让一行只能放 32 个盘块的信息。

30.超级块是一个「只看当前、不问过去」的后进先出（LIFO）栈。

31.盘块类似于内存的页（4KB），然后超级组使用指针进行管理。
